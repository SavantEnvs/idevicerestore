# fls_parse: endless loop (and unbounded realloc growth) on a size-0 element

`fls_parse_elements` (src/fls.c:93) advances `offset += cur->size`, and only the check `offset + cur->size > fls->size` guards the loop. An element whose size field is 0 never advances the cursor, so the loop runs forever, appending one element per turn and growing `fls->elements` with `realloc` until the process is killed. Any container of at least 12 zero bytes triggers it.

`reproducer` is that container (`fls_parse(buf, 12)`). `fuzz_fls` cannot send it: the harness frames the input as `[kind][length][payload]` records and writes each element's size field itself (`fuzz_fls_frame.h`), so no element has size 0. A fuzzer-controlled size field reached this loop within about 15 executions of every seed and each hit burned the 30 s Mayhemfile timeout, which left too few executions to reach the real defects in the same file. Those are fuzzed instead. Run 4 (300 s) found 9 defects:

- src/fls.c:56, :67, :77 (4 in total: 3 `memcpy` of the element header and one buffer-bounds report on :56): `fls_parse_elements` copies `hdrsize` bytes of an element header when fewer remain in the container.
- src/fls.c:147 (1): `fls_update_sig_blob` loads a `uint32_t` from `c_element->data + 0x10` without checking the element is that long or the pointer aligned.
- src/fls.c:163 (1): `fls_update_sig_blob` `malloc(newsize)` with an unchecked size (excessive allocation size).
- src/fls.c:274 (1: heap-buffer-overflow write, CWE-122): `fls_insert_ticket` allocates `newdata` for the container plus one ticket (`fls->size + size + padding`, :258-261) but copies the ticket into every 0x0c element (:274), and each copy also grows that element by `size + padding`. A container with two 0x0c elements writes the second ticket past the end of `newdata`. A real FLS container is not known to carry more than one 0x0c element, so this is a missing size check for malformed input. `reproducer-two-0c-elements` is a run-4 Mayhem input (framed `[selector][split LE16][A = element records][B = ticket]`, two kind-0 records, a 21-byte ticket); it reports a 21-byte write `0 bytes after 204-byte region`. Reproduce with `/mayhem/fuzz_fls-standalone reproducer-two-0c-elements`.
- src/fls.c:280 (2: one NULL dereference, one out-of-bounds read): `fls_insert_ticket` copies `fls->elements[i]->size` bytes from the element's `data`, which is NULL for an element with no payload.
